# 首页分析任务面板默认折叠

## Goal

首页存在运行中的分析任务时，缩减分析任务面板默认占用的高度，把侧栏空间优先留给个股工作区，改善个股浏览和操作体验。

## Background

- 首页侧栏在 `apps/dsa-web/src/pages/HomePage.tsx` 中按“分析任务面板 + 个股工作区”纵向排列。
- `TaskPanel` 只在存在 `pending`、`processing` 或 `cancel_requested` 任务时渲染。
- 当前任务明细区最大高度为 `16rem`，会压缩下方使用 `flex-1` 的个股工作区。
- 当前标题栏已经展示分析任务标题，以及进行中、等待中的任务数量；面板没有整体折叠能力。
- 桌面侧栏和移动端首页抽屉复用同一份 `TaskPanel`。
- 仓库已有折叠交互约定和 `TaskPanel` 独立测试，可沿用现有图标、键盘操作和无障碍模式。

## Requirements

- 有活跃分析任务时，分析任务面板默认以折叠状态出现。
- 桌面侧栏和移动端首页抽屉使用一致的默认折叠行为。
- 折叠状态保留标题栏及任务数量摘要，隐藏任务明细列表，确保用户仍能知道任务正在执行。
- 标题摘要分别展示进行中、等待中和取消中的任务数量；只有对应数量大于零时才显示该项。
- 整个标题栏作为展开/收起按钮，并在右侧显示随状态旋转的箭头；鼠标、触屏和键盘均可触发。
- 展开状态仅保留在当前任务面板实例中，不写入浏览器存储；刷新页面、重新进入首页，或面板消失后因新任务重新出现时，恢复默认折叠。
- 面板持续显示期间，任务进度和列表更新不得擅自改变用户选择的展开状态。
- 展开后保留当前任务明细、运行流入口、进度、诊断信息和滚动行为。
- 折叠交互支持键盘操作，并通过 `aria-expanded` 和可理解的中文、英文标签表达当前状态。
- 不改变任务拉取、实时更新、完成后移除及个股工作区的数据逻辑。

## Acceptance Criteria

- [x] 有活跃任务时，首次显示的面板默认折叠，任务条目和进度明细不可见。
- [x] 折叠时仍显示“分析任务”，以及当前非零的进行中、等待中和取消中任务数量。
- [x] 只剩 `cancel_requested` 任务时，折叠标题仍明确显示“取消中”数量；中英文界面均有对应文案。
- [x] 点击或键盘触发展开控件后，显示全部现有任务内容；再次触发后恢复折叠。
- [x] 点击标题栏任意非冲突位置均可切换状态，右侧箭头同步表达展开或折叠。
- [x] 展开控件具有与当前状态一致的 `aria-expanded` 和展开/收起可访问名称。
- [x] 无活跃任务时仍不渲染任务面板。
- [x] 面板消失后出现新任务时恢复默认折叠；同一批任务的进度或数量更新不改变用户手动选择的展开状态。
- [x] 桌面侧栏和移动端首页抽屉中的行为一致。
- [x] 现有任务状态筛选、运行流入口和任务信息展示行为不回归。
- [x] `TaskPanel` 定向测试覆盖默认折叠、展开、再次收起和无任务场景。

## Out of Scope

- 不修改后端任务 API、任务生命周期或并发行为。
- 不重排首页侧栏模块，不改变个股工作区自身的高度和滚动实现。
- 不单独折叠某一个任务条目。
