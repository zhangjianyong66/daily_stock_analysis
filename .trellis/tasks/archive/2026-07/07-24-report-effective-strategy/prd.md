# 在分析报告中展示实际使用策略

## Goal

让用户在分析报告中直接确认本次分析实际采用了哪些策略，避免把“策略点位”误认为策略名称，也避免只能在底层 JSON 快照中人工查找。

## Background

- 首页策略菜单当前为单选；手动选择时请求携带 `skills: [<skill_id>]`，选择“默认策略”时不携带 `skills`。
- Web 报告中的“策略点位”只展示理想买点、次优买点、止损和止盈，不展示策略身份。
- 手动选择的策略可能出现在“数据追溯 -> 分析快照”的 `skills` 字段中，但默认策略不会可靠写入该字段。
- 多 Agent 报告可能包含“多策略综合”的支持策略和反方策略，但该内容不是所有报告都有，也不等同于一份统一、权威的“本次实际策略”记录。
- 后端会校验请求策略并处理默认回退；因此仅展示前端请求值可能与实际执行结果不一致。

## Requirements

- 报告需要以普通用户能直接理解的中文展示本次分析策略，不要求用户阅读原始 JSON。
- 策略展示以服务端记录的“后端最终实际执行策略”为唯一权威值，不以首页请求值代替。
- 实际执行策略在报告顶部股票概览区以紧凑标签展示，与股票代码、市场阶段和分析时间处于同一信息层级。
- 顶部标签同时展示实际策略名称与选择来源；来源至少能区分手动选择、系统默认、固定配置和自动路由。
- 用户请求的策略无法使用并改用其他策略时，报告以非阻断警告明确展示“系统回退”、原请求策略和最终实际策略。
- 策略状态语义必须严格区分：未选择时正常使用“系统默认”；行情驱动选择为“自动路由”；用户明确选择完全未兑现才是“系统回退”；多策略仅部分成功为“部分执行”；策略已选中但运行失败为“执行降级”。
- “系统默认”和“自动路由未匹配后采用路由默认候选”均属于正常行为，不显示异常警告。
- 执行超时、工具错误或策略 Agent 失败不得伪装为已成功切换其他策略；报告应保留实际尝试状态并标为“执行降级”。
- 策略身份展示不得新增独立大卡片，也不得与现有“策略点位”合并。
- 多策略场景在空间受限时显示首个策略和剩余数量，并提供查看完整策略列表的交互；移动端不得溢出或遮挡其他概览信息。
- 展示结果必须适用于手动选择、默认回退和历史报告读取。
- 同一份策略身份与来源信息必须覆盖 Web 实时报告、Web 历史报告、Markdown 报告和通知推送，不允许不同用户入口各自推断。
- 不得用当前系统配置反推旧报告的策略，避免配置变化后错误解释历史结果。
- 保持现有“策略点位”含义不变，策略身份使用独立、无歧义的标签。
- 兼容没有策略元数据的旧历史报告。
- 缺少实际策略元数据的旧历史报告显示低强调的“分析策略：未记录”，并说明该报告生成时未保存策略信息；不得隐藏后让用户自行猜测。
- 从历史报告触发“重新分析”时，默认复用该报告记录的实际策略；首页当前存在明确策略选择时，以当前选择覆盖；旧报告策略未记录时使用当前系统默认策略。

## Acceptance Criteria

- [x] 新生成的报告可以直接看到本次分析策略的中文名称。
- [x] 策略名称位于报告顶部概览区，并在桌面端和移动端保持紧凑、可读、无溢出。
- [x] 用户可以从顶部标签区分策略来自手动选择、系统默认、固定配置还是自动路由。
- [x] 请求策略不可用并触发回退时，所有报告入口均明确说明原请求策略、最终策略和非阻断回退状态。
- [x] 正常默认、自动路由、系统回退、部分执行和执行降级在 API 与各报告入口中的含义一致，不互相混用。
- [x] 手动选择策略时，报告展示与后端实际采用的策略一致。
- [x] 使用默认策略时，报告明确展示解析后的默认策略，而不是空白或仅显示“默认策略”。
- [x] Web 实时报告、Web 历史报告、Markdown 报告和通知推送对同一分析记录展示一致的策略身份与来源。
- [x] 旧报告缺少策略元数据时，不根据当前配置伪造历史策略。
- [x] 旧报告顶部显示低强调的“分析策略：未记录”，并可查看缺失原因说明。
- [x] 从历史报告重新分析时默认复用原报告的实际策略，首页明确选择可覆盖，策略未记录的旧报告使用当前系统默认。
- [x] 现有买点、止损、止盈等“策略点位”展示保持不变。
