# 根据 K 线自动匹配分析策略

## Goal

让个股分析在用户没有明确指定具体策略时，使用最近有效的完整日 K 线识别当前形态，自动选择一个最适合本次任务的分析策略；无法可靠匹配时使用原有默认策略解析链路兜底。匹配结果只作用于本次分析，不修改配置，也不影响下一次任务重新判断。

## Background

- 仓库已有最近 60 个交易日的确定性 K 线形态识别和策略推荐服务，但当前只在分析完成后生成报告附件，不参与实际策略选择。
- 现有个股默认策略解析顺序为 `DEFAULT_ANALYSIS_SKILL > AGENT_SKILLS > 内置 metadata 默认`；本任务完成后，该顺序保留为自动匹配失败时的兜底顺序。
- 用户明确选择具体策略时仍具有最高优先级。问股聊天和大盘复盘不进入本功能。
- 异步任务当前会在入队时冻结 `SkillPromptState`；自动匹配也必须保持配置冻结和历史快照契约。
- 后端实际执行策略快照是历史、API、Web、Markdown 和通知的唯一事实来源，不得按当前行情或配置重算旧报告。

## Requirements

### 默认选择与入口

- R1：除问股聊天和大盘复盘外，首页单股、自选股批量、同步/异步分析 API、CLI 和定时个股分析，在没有明确传入具体策略时默认执行自动匹配。
- R2：用户本次明确选择具体策略时直接执行该策略，不读取 K 线改写选择；优先级为“本次具体选择 > 自动匹配 > 冻结兜底策略”。
- R3：首页策略菜单把“自动匹配”作为默认选中项，并保留所有具体策略选项。`DEFAULT_ANALYSIS_SKILL` 的配置、设置页和首页快捷设置改为“自动匹配失败后的兜底策略”语义，不允许把自动匹配本身保存成该配置值。
- R4：首页“重新分析”始终按操作时菜单的当前选择执行：当前为自动匹配则重新判断最新合格 K 线，当前为具体策略则执行该策略；不得隐式复用历史报告的实际策略。

### K 线输入与任务隔离

- R5：自动匹配只使用已收盘的完整日 K 线。盘中未完成日线和实时行情不得参与策略选择，但仍可按现有流程参与后续分析。
- R6：最后一根输入 K 线必须等于该市场最近一个已完成交易日；周末和节假日使用最近交易日。日线过期、交易日无法可靠确定、字段不完整、识别异常或少于 10 根时不匹配并进入兜底。
- R7：支持项目已支持的全部个股市场和场内 ETF；具体形态仍须满足检测器自身窗口要求。自动匹配不得增加 ETF 专用评分、买卖、仓位或止损规则。
- R8：匹配结果是每只股票、每次任务独立的不可变运行状态。批量并发任务不得通过共享 Pipeline/Analyzer 状态相互覆盖；结果不得写回 `DEFAULT_ANALYSIS_SKILL`、`AGENT_SKILLS` 或任何后续任务缓存。
- R9：自动匹配不强制切换分析引擎。已开启 Agent 模式时 Agent 使用匹配策略；未开启时普通分析流程使用匹配策略提示；用户明确选择具体策略时沿用现有分析引擎选择行为。

### 确定性映射与冲突处理

- R10：形态识别、报告推荐和自动选择必须复用同一份确定性映射数据，不调用 LLM 选择策略，不维护平行规则表。
- R11：一次任务只执行一个最高优先级策略，其他命中项仅作为候选依据保存，不参与本次策略提示。
- R12：首期映射为：
  - 放量突破 20 日高点、大阳线 -> 放量突破。
  - 一阳夹三阴 -> 一阳夹三阴。
  - 缩量回踩 -> 缩量回踩。
  - 早晨之星、看涨吞没、双底、锤子线 -> 底部放量。
  - 箱体震荡 -> 箱体震荡。
  - 黄昏之星、看跌吞没、流星线、上吊线、大阴线 -> 情绪周期，按风险复核模式执行，不得表述为进攻性买入。
  - 十字星、倒锤子线和方向不明确形态不产生匹配。
- R13：看涨与看跌候选冲突时风险优先。最新完整 K 线确认的强看跌反转优先选择“情绪周期”；否则按映射优先级、信号强度和时效确定唯一结果。弱信号或较早且未获最新走势确认的信号不得覆盖最新强信号。
- R14：检测器中“一阳夹三阴”等声明使用最近窗口的规则必须真实读取最近 K 线，不能读取 60 日窗口开头的数据；相关修复同时作用于报告推荐和自动选择。

### 兜底、快照与展示

- R15：异步任务入队时冻结兜底 `SkillPromptState` 和可调用策略目录；同步、CLI 和定时任务在本次运行开始时冻结。匹配成功从该目录生成本次策略状态；匹配失败使用冻结的 `DEFAULT_ANALYSIS_SKILL > AGENT_SKILLS > 内置默认`，执行中配置变化不得影响任务。
- R16：K 线数据不足、过期、日历不可用、无可靠形态、候选策略不可调用或识别异常时主分析继续，并使用冻结兜底策略。报告必须区分具体原因。
- R17：匹配和报告附件必须复用同一次 K 线加载与形态识别结果，不允许分析前选一次、分析后重新读取再生成另一份结论。
- R18：`strategy_execution` 快照在保持旧字段兼容的前提下，保存自动选择上下文：选择模式、完整日线截止日期、命中形态、候选策略、最终策略和兜底原因。匹配成功使用 `source=auto`；未匹配并兜底时使用明确的 fallback 语义。
- R19：Web 实际执行策略区域显示“本次选择：自动匹配”“实际策略”“匹配依据/完整日线截止日”；兜底时显示数据不足、日线过期、形态不明确或候选不可用。历史、Markdown 和通知读取同一持久化快照，不重新计算。
- R20：旧报告、旧客户端和显式具体策略请求保持兼容；自动匹配局部失败不得导致个股主分析失败。

### 文档与语言

- R21：新增或调整的用户文案覆盖现有 Web UI 语言和报告中文、英文、韩文语义；更新 `docs/CHANGELOG.md`、策略选择/完整指南、相关 Trellis 规范和 `AGENTS.md` 中的默认策略契约。中英文指南需同步评估并保持一致。

## Acceptance Criteria

- [ ] 未明确指定策略的首页、API、CLI、定时和批量个股任务会在分析前自动匹配；明确选择具体策略时不会执行自动匹配。
- [ ] 每只股票只执行一个确定性策略；同一输入始终得到同一结果，强看跌冲突优先进入情绪周期风险复核。
- [ ] 盘中任务只使用上一有效完整交易日，周末/节假日使用最近交易日；过期、部分、少于 10 根或无法可靠判断完整性的日线触发冻结兜底。
- [ ] 自动匹配适用于所有已支持个股市场和场内 ETF，数据不满足时不阻断主分析。
- [ ] 批量并发两只股票可以得到不同策略，互不串线；后续新任务会重新匹配，不复用上次运行结果。
- [ ] 自动匹配不改变当前分析引擎；Agent/普通分析都能收到本次匹配策略，显式具体策略的既有引擎行为不变。
- [ ] 报告形态附件和实际策略快照来自同一次识别；实时、历史、Markdown、通知显示的实际策略、依据、截止日和兜底原因一致。
- [ ] 首页默认显示自动匹配；重新分析按当前菜单选择，不按历史实际策略偷偷覆盖；默认策略快捷设置明确表示配置的是兜底策略。
- [ ] `DEFAULT_ANALYSIS_SKILL`、`AGENT_SKILLS` 和内置默认的原解析顺序在自动匹配失败时保持，异步任务入队后的配置变化不会改变兜底结果。
- [ ] 旧报告缺少新增上下文字段时正常展示；旧客户端忽略新增可选字段不受影响。
- [ ] 覆盖映射、冲突、完整日线/时效、显式优先、兜底冻结、并发隔离、同步/异步/CLI 路径、快照往返和 Web 交互测试。

## Out of Scope

- 问股聊天和大盘复盘的自动策略匹配。
- 一次分析组合执行多个策略。
- 让 LLM 自由选择策略或从报告文字反推实际策略。
- 修改各具体策略内部交易规则，或新增 ETF 专用决策护栏。
- 周线、分钟线或多周期联合路由。
- 把本次匹配结果写回配置、保存为下一任务默认，或用历史报告重新推断当前策略。
